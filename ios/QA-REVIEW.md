# iOS 原生客服端审查记录（无 APNs 签名版 / API v2）

## 2026-09-29 / build 22：聊天交互复查

- 底部占位的 `onAppear` 只是 LazyVStack 预加载，不能证明消息可见。现改为测量列表内容底部与实际视口，已读还需满足前台、聊天页可见和最新消息已布局。
- 删除全局 `defaultScrollAnchor(.bottom)`，避免系统在内容或容器变化时与手动滚动竞争。滚动任务统一取消、合并，移除新消息动画与 80ms 非动画校准混用；首次定位期间隐藏未定位内容。
- 显式测量的消息视口位于输入区上方并裁剪绘制范围。键盘、引用栏、多行草稿、附件面板、旋转及翻译/图片撑高内容都会触发保持底部；用户拖动时取消校准和延迟已读。
- 阅读历史时保留位置和新消息提示；SSE 与轮询发现同一 ID 时不会重复累计。
- 打开资料、图片、全文、选中文字或附件选择器，以及退后台期间不清未读。关闭弹层后按实际可见位置恢复，离开聊天页取消滚动和已读任务。
- 乐观消息与回包使用同一个幂等 ID；不再用内容比较吞掉相同文字的第二条回复。旧轮询回包不能覆盖更新后的消息快照。
- 发送失败不覆盖随后输入的草稿，引用一并恢复；超长正文连同引用在发送前校验。常用语追加而非替换草稿，点击表情面板的键盘按钮会回到输入。
- 会话结束/重新打开防止重复点击；搜索、前后台恢复、快速连续推送跳转增加取消与过期响应检查。退出登录立即清理本地会话。
- SSE 接收循环不再等待在线状态请求；慢速在线上报不会堵住后续消息。

本次没有修改网页后台、客户插件和服务端。最低系统仍为 iOS 17。

### 验证边界

- 本地：所有 Swift 文件语法解析、工程文件引用、Git diff 格式检查。
- 新增交互状态回归用例并接入 GitHub Actions；Windows 无 Xcode，Swift 用例执行及 IPA 编译必须由 macOS 构建完成，不能将语法解析视为已通过编译。
- 真机重点：iOS 26 打开有图片/长文本的未读会话，同时让客户连发消息；开关键盘/表情/工具面板、输入五行文字、添加/取消引用，确认最后一条始终在输入框上方。
- 真机重点：上滑阅读历史后收到文字/图片，位置不被拉走；点“回到最新”再清未读。资料/大图/全文弹层期间收到消息，返回后才按可见情况清未读。
- 真机重点：弱网发送后继续输入，失败后两段内容均保留；连续发送相同文字、上传图片、快速返回和切换会话，确认无消息消失、重复及错误跳转。

## 已修复的高风险问题

1. 临时断网会清除有效 token、强迫重新登录：现在只有服务器明确返回 401 才退出。
2. 每 2 秒下载全部聊天记录，历史多时容易卡顿和耗电：改为 SSE 实时事件流，并以 4–5 秒轻量对账兜底。
3. 发送消息与后台刷新并发时可能闪烁、短暂消失或重复：增加本地临时消息、ID 去重和请求序号保护。
4. 永久删除会话没有二次确认：增加不可恢复警告；正常流程改为结束/重新打开会话。
5. 已结束会话收到客户新消息后仍留在归档：现在自动重新打开并回到处理中。
6. App 启动时无法判断服务器是否部署了原生接口：增加 `/api/native/health` API v2 检查。
7. 图片选择入口放在 Menu 内可能无法稳定弹出系统选择器：改用系统 `photosPicker` 呈现状态。
8. 大文件先完整读入内存、最后才由服务器拒绝：读取前检查 20MB，文件 I/O 移出主线程。
9. 旧数据中某条消息字段为空会导致整个会话解码失败：模型改为兼容空字段解码。
10. 多个搜索/刷新请求返回顺序不同时，旧结果可能覆盖新结果：增加请求序号保护。
11. 原尺寸照片压缩耗时且容易超过代理上传上限：改为后台缩放、分级压缩到约 900KB。
12. 发送已落库但成功回包丢失时，人工重试会产生重复消息：加入客户端消息 ID、服务端幂等写入和成功回查。
13. 访客插件断线重连会重复追加历史消息：恢复历史前按消息 ID 重建，并对实时事件二次去重。
14. 网页快速切换会话时旧请求可能覆盖新窗口：会话加载增加请求序号和当前会话校验。
15. 图片每次重新进入都重复解码：在磁盘 HTTP 缓存之外增加 80MB 解码图片内存缓存。
16. 从列表直接打开未读会话偶尔停在第一条：增加底部默认锚点和首次布局双阶段校准。
17. 查看历史时收到新消息或图片加载会抢走当前位置：保留当前位置并显示“回到最新 / N 条新消息”，回到底部后再清未读。
18. 不同会话、退出登录或切换服务器可能残留导航状态：聊天页按会话 ID 隔离状态，并清理待跳转会话。
19. 部分设置操作在客户端不可用时会静默显示成功：改为强制取得已认证客户端，并统一处理登录失效。

## 操作体验升级

- 未读优先的处理中队列，以及未读、已结束、全部筛选。
- 实时连接状态绿点/重连橙点。
- 乐观发送和发送中、已发送、已送达、已读状态。
- 客户与客服双方正在输入提示。
- 按会话保存未发送草稿。
- 常用语搜索、文字复制、撤回确认。
- 图片原生大图预览、双击和捏合缩放。
- 会话标签、内部备注、来源页面和结束会话入口。
- 新客户消息前台触觉提醒。

## 当前仍不等同于商业客服平台的部分

- 目前是单管理员账号，没有多人分配、抢单、@成员和权限系统。
- 没有语音、视频、AI 回复、知识库、订单侧栏和多渠道聚合；现有翻译使用 iOS 系统能力。
- 此构建不申请 APNs entitlement，后台和锁屏通知依赖 Bark。
- 当前消息历史一次加载全部。个人低流量场景足够；如果 Crisp 导入量达到数万条，应继续增加游标分页。
- Windows 环境只能做静态检查，最终 Swift 编译和真机交互仍需在 Mac 的 Xcode 中执行。

## 真机验收清单

- 首次填域名，确认服务器健康接口返回 API v2。
- 飞行模式启动后恢复网络，确认不掉登录并自动变绿点。
- 电脑网页端和 iPhone 同时打开，互相发送文字、图片和文件。
- 快速连续发送多条文字，确认不重复、不闪烁、不乱序。
- 锁屏、切后台和划掉 App 后测试 Bark 通知；回到原生 App 后应自动补齐消息。
- 结束会话后让访客再次发消息，确认自动回到处理中。
- 测试 20MB 以上文件、无扩展名文件和服务器不允许的扩展名。
- 测试长按复制/撤回、图片缩放、草稿恢复和删除确认。
- 不点 Bark 通知，直接从 App 列表打开未读会话，确认停在最新消息而不是第一条。
- 上滑查看历史后让客户发新消息，确认当前位置不跳动、出现新消息按钮，点按钮后回到底部并清未读。
