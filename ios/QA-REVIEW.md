# iOS 原生客服端审查记录（无 APNs 签名版 / API v2）

## 已修复的高风险问题

1. 临时断网会清除有效 token、强迫重新登录：现在只有服务器明确返回 401 才退出。
2. 每 2 秒下载全部聊天记录，历史多时容易卡顿和耗电：改为 SSE 实时事件流，15 秒低频兜底。
3. 发送消息与后台刷新并发时可能闪烁、短暂消失或重复：增加本地临时消息、ID 去重和请求序号保护。
4. 永久删除会话没有二次确认：增加不可恢复警告；正常流程改为结束/重新打开会话。
5. 已结束会话收到客户新消息后仍留在归档：现在自动重新打开并回到处理中。
6. App 启动时无法判断服务器是否部署了原生接口：增加 `/api/native/health` API v2 检查。
7. 图片选择入口放在 Menu 内可能无法稳定弹出系统选择器：改用系统 `photosPicker` 呈现状态。
8. 大文件先完整读入内存、最后才由服务器拒绝：读取前检查 20MB，文件 I/O 移出主线程。
9. 旧数据中某条消息字段为空会导致整个会话解码失败：模型改为兼容空字段解码。
10. 多个搜索/刷新请求返回顺序不同时，旧结果可能覆盖新结果：增加请求序号保护。
11. 原尺寸照片压缩耗时且容易超过代理上传上限：改为后台缩放、分级压缩到约 900KB。
12. 发送已落库但成功回包丢失时，人工重试会产生重复消息：加入客户端消息 ID、服务端幂等写入和成功回查。
13. 访客插件断线重连会重复追加历史消息：恢复历史前按消息 ID 重建，并对实时事件二次去重。
14. 网页快速切换会话时旧请求可能覆盖新窗口：会话加载增加请求序号和当前会话校验。
15. 图片每次重新进入都重复解码：在磁盘 HTTP 缓存之外增加 80MB 解码图片内存缓存。

## 操作体验升级

- 未读优先的处理中队列，以及未读、已结束、全部筛选。
- 实时连接状态绿点/重连橙点。
- 乐观发送和发送中、已发送、已送达、已读状态。
- 客户与客服双方正在输入提示。
- 按会话保存未发送草稿。
- 常用语搜索、文字复制、撤回确认。
- 图片原生大图预览、双击和捏合缩放。
- 会话标签、内部备注、来源页面和结束会话入口。
- 新客户消息前台触觉提醒。

## 当前仍不等同于商业客服平台的部分

- 目前是单管理员账号，没有多人分配、抢单、@成员和权限系统。
- 没有语音、视频、翻译、AI 回复、知识库、订单侧栏和多渠道聚合。
- 此构建不申请 APNs entitlement，后台和锁屏通知依赖 Bark。
- 当前消息历史一次加载全部。个人低流量场景足够；如果 Crisp 导入量达到数万条，应继续增加游标分页。
- Windows 环境只能做静态检查，最终 Swift 编译和真机交互仍需在 Mac 的 Xcode 中执行。

## 真机验收清单

- 首次填域名，确认服务器健康接口返回 API v2。
- 飞行模式启动后恢复网络，确认不掉登录并自动变绿点。
- 电脑网页端和 iPhone 同时打开，互相发送文字、图片和文件。
- 快速连续发送多条文字，确认不重复、不闪烁、不乱序。
- 锁屏、切后台和划掉 App 后测试 Bark 通知；回到原生 App 后应自动补齐消息。
- 结束会话后让访客再次发消息，确认自动回到处理中。
- 测试 20MB 以上文件、无扩展名文件和服务器不允许的扩展名。
- 测试长按复制/撤回、图片缩放、草稿恢复和删除确认。
